# Wind Study 1.3.2 — серии экспериментов ВЭУ

Исходники Python для Windows. Без BAT, установщика, сервера и Node.js.
Откройте папку в IDE и запускайте **main.py как обычный Python-файл**.
Один раз установите библиотеки в интерпретатор проекта:

```text
python -m pip install -r requirements.txt
```

После этого запускайте main.py кнопкой Run. Для добавления в свой проект
скопируйте папку `windstudy`, папку `data` и (по желанию) `cache`.
Код своей точки входа:

```python
from windstudy.ui import run


def main():
    return run()


if __name__ == "__main__":
    raise SystemExit(main())
```

Если приложение PySide6 уже существует, можно встроить `windstudy.ui.Window`
в свой запуск. Не создавайте вторую QApplication. Обычный main выше предназначен
для самостоятельного запуска этого окна.

## Быстрая загрузка всего пула: версия 1.3

1. Обновите исходники и зависимости (команда ниже).
2. В поле «Способ скачивания» выберите **Архив AWS → на диск**.
3. Оставьте флажок **Скачать для всего пула**.
4. Задайте **Скачать: 2001.01.01 — 2025.12.31**.
5. Выберите постоянную папку кэша на диске с запасом места. Для первого полного
   архива разумно оставить 30 ГБ свободными; это запас, не измеренный размер архива.
6. Для облачного архива можно установить 3 параллельных запроса (допустимо 1–5).
7. Нажмите **Скачать данные**. Подготовка экспериментов для всего пула не нужна.

Облачные данные сохраняются в `cache/power_archive_v1`. Остановка и повторный
запуск сохраняют прогресс: готовые блоки проверяются по SHA-256 и не скачиваются
заново. Повреждённые блоки повторяются. Папку архива можно перенести вместе с
остальным кэшем; после этого выберите её родительскую папку в приложении.
Не запускайте одновременную запись двух копий программы в одну папку кэша.

Для текущего пула из 9172 ячеек за 2001–2025 нужны **3640 блоков скоростей**,
а также небольшие метаданные и координаты. Точечный годовой API потребовал бы
229300 запросов при пустом кэше. Это сокращение числа запросов примерно в 63 раза,
а не обещание такого же ускорения по времени. Полный архив при разработке не скачивался.

Выбран временной Zarr-архив NASA: блок содержит до 70128 часов × 5 × 5 ячеек
одного параметра. Поэтому вместе с нужными датами/точками в блок могут попасть
соседние ячейки и годы; это устройство источника, а не расширение выборки.
Сохраняются оба параметра WS10M/WS50M. Формат на диске — сжатые NPZ-блоки
с отдельными рядами ячеек, SQLite-индекс и снимок метаданных. Расчёт читает
конкретную ячейку, не распаковывая весь географический блок. Всё в UTC.

**Расчёт не читает облако.** Если нужные данные есть на диске, интернет не нужен.
Для расчёта подготовьте эксперименты, выберите расчётные даты и нажмите кнопку 3.
Если архив ещё не полон, автоматическая дозагрузка недостающих ячеек выполняется
прежним точечным API только за расчётные даты. Массовый архив заполняется кнопкой 2.
Старые API-ответы продолжают использоваться: сначала локальный архив,
затем API-кэш для отсутствующих или непригодных значений. Пул и формулы не меняются.

Статус complete у архивной загрузки означает, что нужные облачные блоки сохранены.
Пригодность каждого нужного часа проверяется перед расчётом: заполненный
облачный блок может содержать NaN на ещё не опубликованных датах. Такие значения
не заменяются нулями и не участвуют в финальной выборке. Существующие полные
блоки закрепляются локально; автоматическое обновление пересмотренных NASA
значений пока не выполняется. Для свежих дат с пропусками используйте API-дозагрузку.

Совпадение координат и непрерывность часовой оси проверяются при создании архива.
При продолжении с недостающими блоками проверяется совместимость метаданных NASA.
В result.json сохраняются URL, SHA-256 исходных блоков и локальных файлов.
Сравнение реального блока с прежним API-кэшем за 2023 год: 8760 часов обоих
параметров, без пропусков, максимальное абсолютное отличие около 0.00003 м/с.
Архив сохраняет исходные float32; дополнительного округления нет.

Для архива используется numcodecs 0.17.0 (готовые сборки для Python 3.12–3.14, Windows x64).
Библиотека zarr больше не нужна: блоки Zarr v2 читаются напрямую через кодеки.
В requirements запрещена сборка numcodecs из исходников.
Установите в **том же интерпретаторе**, которым запускается main.py:

```text
python -m pip install -r requirements.txt
```

## Восстановление координат из ID

Для `M2:rRRR:cCCC`: широта = −90 + 0.5 × RRR;
долгота = −180 + 0.625 × CCC. Это центр ячейки, градусы WGS84.
Отрицательная долгота означает западную. Нумерация начинается с нуля.
Сохраните plan.json, Excel и data/pool.sqlite: позже можно построить карту
всех экспериментов, отдельных выборок и частот повторения ячеек.

## Работа

Архивная загрузка и расчёт имеют независимые диапазоны дат.
Кнопка расчёта автоматически дозагружает недостающее для своей серии.
Начальная дата включает 00:00, конечная — 23:00, всё в UTC. 29 февраля учитывается.
Например, архив 2001.01.01–2024.12.31 можно использовать для расчёта
2020.01.01–2024.12.31 без повторной загрузки. Даты сохраняются между запусками.

1. Для накопления архива задайте даты **Скачать: от / до**, папку кэша и оставьте
   флажок **Скачать для всего пула**. Состав экспериментов для этого не нужен.
   Если требуется только небольшая загрузка, снимите флажок и подготовьте серию.
2. **Проверить наличие** показывает покрытие ответами и число недостающих блоков.
   Это проверка локального индекса, без запросов к NASA. Качество часов проверяется
   при загрузке новых ответов и перед расчётом.
3. **Скачать данные** запрашивает только недостающие интервалы блоками до
   календарного года в режиме точечного API; в режиме AWS — облачными блоками. По умолчанию работает 1 запрос (настройка 1–5), старты разнесены минимум на 2 секунды.
   При сетевых сбоях есть повторы с паузами; большой запрос после неудач дробится.
   Остановка сохраняет все завершённые блоки. Для продолжения повторите загрузку
   с той же папкой кэша. Журнал `download_*.json` сохраняется в этой папке.
4. Для расчёта задайте N (например 512), R (100), seed, высоту и характеристики.
   **Подготовить эксперименты** формирует состав и показывает число уникальных ячеек,
   покрытие и число неиспользованных ячеек. Интернет не используется.
5. Выберите **Рассчитать: от / до** и нажмите **Рассчитать → Excel**.
   Сначала проверяются нужные часы всех уникальных ячеек. При недостатке данных
   автоматически запускается дозагрузка для ячеек серии за расчётный период.
   Диапазон архивной загрузки и флажок всего пула на эту дозагрузку не влияют.
   После загрузки данные проверяются повторно. Вычисления моделей начинаются
   только при наличии всех пригодных часов. Иначе сохраняется неполный отчёт
   с причинами; вымышленные значения и неполные итоговые выборки не формируются.
6. Меняйте расчётные даты, высоту, мощности и формулы и запускайте расчёт повторно.
   Изменение этих параметров не меняет уже подготовленные географические выборки.
   Изменение N, R, seed или пула требует повторной подготовки экспериментов.

Готовые месячные ответы прежних версий автоматически используются вместе с
новыми годовыми. Демонстрационный кэш в Git не включён. При первом запуске скачайте данные для выбранных точек.
Новые ответы с пропусками помечаются: следующая загрузка повторит неполные
интервалы. Это не гарантирует, что NASA уже исправила исходные данные.
Если отсутствует WS10M, но есть WS50M, расчёт на 50 м допустим; для других высот
действуют проверки ниже. Нули на другой высоте — методическое ограничение,
повторная загрузка не обязательно поможет.

Каждый расчёт создаёт отдельную папку с `plan.json`, `result.json`, `report.xlsx`.
Финальные таблицы средних и медиан появляются только при успешной обработке
всей серии. Почасовая мощность считается один раз на уникальную ячейку в рамках
запуска. КИУМ ячейки считается по всем часам выбранного периода вместе,
а не как невзвешенное среднее годовых КИУМ. Затем для каждого эксперимента
находятся среднее и медиана по его ячейкам, и статистика этих R результатов.

В режиме точечного API архив всего пула за 2001–2024 — до 9172 × 24 = 220128 годовых запросов
при пустом кэше. Это длительная первоначальная загрузка, не несколько минут.
Объём JSON может составить десятки гигабайт; выбирайте диск с запасом места.
Программа не загружает весь архив в память: расчёт обрабатывает одну ячейку
за раз. Декодированные массивы сохраняются в `cache/decoded_v1` для ускорения
повторных расчётов. Эту подпапку можно удалить при закрытом приложении — она
будет восстановлена из SQLite. Сам `meteo_cache.sqlite` удалять не нужно.

## Результаты Excel

- **Сводка**: параметры, статус, число включений, уникальные ячейки, покрытие,
  ошибки и определения единиц.
- **Средние**, **Медианы**: R строк, отдельные столбцы трёх моделей; КИУМ в долях.
- **Статистика**: среднее, медиана, min/max, размах, выборочные дисперсия/СКО,
  P05/P95, квартили, межквартильный размах. Для R=1 дисперсия и СКО пусты.
- **Модели**: введённые характеристики и мощности.
- **Модель 1/2/3**: КИУМ, эквивалентные часы и кВт·ч каждой уникальной ячейки.
- **Частота**, **Покрытие**: частота использования и накопление уникальных ID.
- **Состав**: все ячейки каждого эксперимента с порядком и seed.

Это числовой снимок расчёта, не интерактивная книга с Excel-формулами.
Пересчёт выполняется программой. Почасовая погода остаётся в локальном архиве и API-кэше: у Excel
есть ограничение строк, поэтому она не дублируется в итоговой книге.
Книга записывается встроенным OOXML-экспортёром стандартной библиотеки Python;
устанавливать Excel для формирования отчёта не требуется.

## Методика и ограничения

Общий пул: 9172 ячейки; его геометрия унаследована из версии 0.5.0, маска по
условию исследования на 02.10.2026. Это не новая подготовка границ.
Водоёмные ячейки не исключаются. Пул один для всех экспериментов.
Соболь 2D scramble=True, seed=base_seed+номер-1; точки вне пула и повторы
внутри эксперимента пропускаются. Между экспериментами повторы допустимы.
Все модели используют одинаковые ячейки. Отбор не объявляется простым
равновероятным случайным отбором. Точные списки и версии SciPy/NumPy в plan.json.

Формула рабочего участка: (V^n−Vmin^n)/(Vnom^n−Vmin^n), n=1,2,3.
До Vmin ноль; от Vnom до Vmax включительно номинал; выше Vmax ноль.
Начальная мощность 1000 кВт — условное редактируемое значение, не реальная ВЭУ.
КИУМ от масштаба номинальной мощности не зависит, кВт·ч зависят.

Погода: NASA POWER WS10M/WS50M, почасовые данные UTC начиная с 01.01.2001.
Можно выбрать произвольные целые дни до вчерашнего дня UTC включительно,
но последние дни могут ещё отсутствовать у NASA. Доступность конкретных
параметров и часов проверяется по ответу сервера.
На 50 м применяется WS50M, в том числе нулевая скорость. На другой высоте:
alpha(t)=ln(WS50M/WS10M)/ln(5), v(h,t)=WS50M*(h/50)^alpha(t).
Для этого режима обе скорости должны быть строго положительными. Пропуски,
нули и нечисловые результаты останавливают серию. Alpha не обрезается и не
заменяется на 1/7. Это консервативная техническая обработка до согласования
более сложных правил. Коррекция плотности не выполняется.

Исходный JSON, дата загрузки, URL и SHA-256 хранятся в meteo_cache.sqlite;
хеши использованных ответов включены в result.json. Совместимо с кэшем 0.4/0.5.
Неполные ответы сохраняются с отметкой качества и повторяются при следующем
скачивании нужного диапазона. При перекрытии ответов применяется более свежий
ответ; использованные URL и хеши фиксируются. Автоматической подмены ячеек нет.
Счётчик наличия не гарантирует качество каждого часа. Повреждение исходного
SQLite/хеша останавливает расчёт; автоматически повреждённые байты не исправляются.

Статистика описывает чувствительность к географической выборке, не точность
относительно реальных ВЭУ и не неопределённость климатической модели. Табличные
кривые поддержаны каталогом; автоматическое ранжирование моделей пока не реализовано.
Ограничения интерфейса: 1–9172 точек, 1–10000 экспериментов, высота 1–300 м.
Большие серии требуют больше памяти на списки ID и Excel; обычный сценарий —
256/512 точек и 100 экспериментов.

## Каталог формул и табличных ВЭУ (обновление)

Параметры моделей теперь задаются кнопкой **Характеристики и формулы…**, а не
таблицей в главном окне. Единый файл `data/catalog.json`, схема версии 1:

- `formulas` — список аппроксимаций;
- `curves` — список реальных табличных характеристик.

У записи есть постоянный `id`, отображаемое `name`, флаг `enabled`,
`nominal_kw`. Название и номинал следует задавать по паспорту.
Редактор показывает метаданные JSON и (для ВЭУ) отдельную таблицу точек.
Из Excel можно вставлять **два столбца без заголовков**: скорость и мощность.
Десятичная запятая поддерживается. Сохраните запись до переключения на другую.
Для ручного добавления записи есть отдельные кнопки ВЭУ/формулы.

Три кривые пользователя от 07.10.2026 добавлены без изменений исходных чисел:
скорости 2…25 м/с, мощность кВт, пустые клетки = JSON `null`.
Они пока `enabled=false`, потому что номинал и поведение за пределами таблиц
не заданы. Это не нулевые мощности! Ненулевые данные первой кривой заканчиваются
при 16 м/с, второй — при 23, третьей — при 22 м/с.

Перед включением табличной кривой:

1. Укажите `nominal_kw`.
2. Установите `below_table` и `above_table`: `zero` (ноль) или `hold`
   (крайнее известное значение вне диапазона). Если нужен другой закон,
   сначала дополните таблицу или расширьте реализацию — не выбирайте режим наугад.
3. Заполните отсутствующие внутренние точки или явно удалите строку, если
   сознательно хотите линейную интерполяцию между соседними известными точками.
4. Укажите `enabled=true` и сохраните запись.

Линейная интерполяция применяется в известном диапазоне. При самом первом и
последнем известных узлах используется его табличная мощность; внешнее правило
действует строго за диапазоном. Значения выше Pном НЕ обрезаются: исходные 101.06,
101.08 и 100.79 кВт сохраняются. Паспортная hub_height_m хранится, но общий расчёт
всех моделей выполняется на высоте из главного окна.

### Формулы

`expression` — нормированная мощность p(v) на рабочем участке; `parameters` —
численные параметры, включая обязательные `v_min`, `v_nom`, `v_max`.
Встроенные три записи дополнительно используют параметр `n` (1,2,3).
Можно добавить, например, `(v-v_min)**a/(v_nom-v_min)**a` с новым параметром `a`.
Это другая формула, не замена уже согласованной разности степеней.

Поддержаны числа, имена параметров, переменная `v`, скобки, операции + - * / **.
Вызовы Python, доступ к файлам, атрибутам и произвольный `eval` не разрешены.
Показатель степени — скаляр в пределах -20…20. Новые функции/кусочные участки
потребуют явного расширения безопасного интерпретатора.

`boundary_rule=zero_ramp_one_zero_inclusive_cutout`: ниже Vmin ноль,
рабочая формула до Vnom, затем единица до Vmax включительно и ноль выше Vmax.
Неверные/отрицательные значения или p>1 у формул вызывают ошибку (не обрезаются).
У табличных ВЭУ p>1 разрешено, потому что оно может содержаться в исходных данных.

В расчёт входят ВСЕ включённые записи обоих видов. Количество столбцов итоговых
выборок и листов по моделям определяется каталогом, а не жёстко задано равным 3.
Excel дополнен листом **Каталог снимок** с полными спецификациями моделей.
Это позволяет точно восстановить, какие таблицы и формулы использованы.
Для больших кривых первичный полный снимок также остаётся в result.json.

Тесты: формулы, интерполяция, значения выше номинала, запрет выполнения кода,
реальный кэш, Excel, покрытие серии, статистика и высота. Массовая загрузка
при разработке не выполнялась. Windows/Excel в этой среде не запускались.

## Сеть и проверка

После неудачных крупных запросов загрузчик уменьшает интервал. Неполный
HTTP-ответ не записывается как готовый блок. Повторы видны в журнале окна.

## Изменения 1.2: HTTP 429 и автоматическая дозагрузка

HTTP 429 включает общую паузу всех работников одной загрузки, а не отдельные
синхронные повторы. Параллельность снижается до 1 до конца операции.
Пауза начинается с 60 секунд и увеличивается до 15 минут; больший Retry-After
сервера учитывается, добавляется небольшой случайный интервал. В окне каждые
5 секунд показывается оставшееся ожидание. Кнопка остановки прерывает паузу.
Уже отправленные запросы не отзываются; новые ждут общего разрешения.
После 6 неудачных попыток запрос завершается ошибкой. При исчерпании повторов
429 очередь прекращает выдавать новые блоки, кэш остаётся для следующего запуска.
Не запускайте несколько копий приложения на одновременную загрузку: ограничитель
общий внутри одной операции, а не между отдельными процессами.

Кнопка «Дозагрузить / рассчитать → Excel» выполняет весь сценарий автоматически.
Если все данные уже пригодны, сетевых запросов нет. Функция calculation.calculate
остаётся автономным расчётным ядром; workflow.run управляет проверкой и дозагрузкой.
Проверки добавлены для общей паузы 429, отмены ожидания, автоматической дозагрузки,
повторного расчёта без сети и отсутствия итоговых выборок при пропусках.

## Исправление установки на Python 3.14 — 1.3.1

Версия 1.3 закрепляла numcodecs<0.16 для Zarr 2. На Windows/Python 3.14
pip пытался собрать numcodecs 0.15.1 из исходников и требовал Microsoft C++.
Теперь зависимость от zarr удалена; используется numcodecs 0.17.0 с готовыми
бинарными сборками. Форматы локального архива и старого кэша не изменены.
Требуется Python 3.12 или новее; для текущей версии проверено наличие готовой
сборки numcodecs для CPython 3.14 Windows x64. Windows-запуск здесь не выполнялся.

Замените windstudy и requirements.txt, затем выполните в терминале проекта:

```text
python -m pip install -r requirements.txt
```

Если ранее самостоятельно установили Zarr 2, он этой программе больше не нужен.
Предупреждение PyCharm о PSReadLine не связано со сбоем numcodecs.

Новый декодер сравнен с прежним Zarr 2 на реальном блоке NASA: все
70128 × 5 × 5 значений WS10M совпадают, включая позиции NaN.


## Исправление блокировки журнала Windows — 1.3.2

При временном отказе доступа к JSON-журналу замена файла повторяется.
Журнал обновляется раз в 30 секунд и при завершении; ошибка его записи
отображается предупреждением и не прерывает скачивание. Каждый готовый
блок по-прежнему немедленно регистрируется в SQLite-индексе. Ошибки записи
самих блоков или индекса остаются причиной неполной загрузки.

Для обновления закройте приложение и замените папку `windstudy` исходниками
из архива. Сохраните свои папки `cache`, `data`, `results` и настройки.
Запустите `main.py`, выберите прежний кэш и повторите загрузку с теми же
датами: блоки с верными контрольными суммами повторно не скачиваются.
